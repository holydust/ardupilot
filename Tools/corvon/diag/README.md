# CORVON G 系列 · SWD 板级诊断

给 `test` 报 `mag: FAIL n=0` 这一类"器件不应答"的情况用。产线烧录时 SWD 探针本来就在位,
所以这两条判据不需要拆板、不需要示波器。

```bash
./i2c-diag.sh          # scan + pullup,默认全跑
./i2c-diag.sh scan
./i2c-diag.sh pullup
```

CPU 会被 halt,跑完自动还原引脚配置并 `reset run`。

## scan —— 总线上有没有东西应答

把 PB6/PB7 从 I2C1 的 AF 切成开漏 GPIO,手工敲 I2C 时序扫 `0x08–0x77`。
I2C 没有最低时钟要求,SWD 一次访问几毫秒完全合法。
扫描前先发 9 个时钟 + STOP,释放可能卡在半个字节里的从机。

| 结果 | 含义 |
|---|---|
| 无任何 ACK | 器件不在总线上(没贴 / 虚焊 / 链路断) |
| 在预期地址 ACK | 器件正常,问题在别处(驱动、时序、参数) |
| 在别的地址 ACK | 地址脚(IST8310 的 `CAD0`/`CAD1`)接错或虚焊 |

## pullup —— scan 回答不了的那个问题

**读到 SCL/SDA 是高,本身什么都不能证明。** 模拟开关断开时 MCU 引脚悬空,
开关引脚到 V+ 的 ESD 二极管靠漏电流就能把它拉到 1。

所以这条测试改为:**把线拉低,然后释放** —— 只有真实存在的上拉才能把它拽回高。
并且在 RS2058 被命令到 MCU 侧和 FC 侧两种状态下各做一次:FC 侧回不来,
正好作为对照,证明开关确实在切换、测试本身有效。

```
开关 → MCU 侧:  拉低释放后 SCL=0 SDA=1   ← SDA 那一路完好,SCL 那一路断
开关 → FC  侧:  拉低释放后 SCL=0 SDA=0   ← 对照组,FC 未接,本来就没上拉
```

I2C 的 SCL 是开漏,**没有上拉就永远产生不了高电平**,任何地址都不会 ACK ——
一条 SCL 上拉缺失就足以解释"扫描全空"。

## 2026-08-20 G2 首片:这两条各自抓到了什么

`test` 报 `mag: FAIL n=0`。先核过固件与原理图,两块板一致,`corvon.init()`
在 `compass.init()` 之前完成模拟开关切换,不存在竞态;IST8310 地址脚
`CAD1→3V3 / CAD0→GND` = `0x0E`,与 hwdef 一致。

`scan` 全空。当时据"空闲读到高 ⇒ 链路完整"判为 U6 焊接不良,**这个推断是错的** ——
回流 U6 后 `scan` 依旧全空。`pullup` 才把故障定位到 **SCL 单边**:

```
MCU_SCL = { U5.9(mux NO1), U7.58(PB6) }     ← 网表确认 MCU 侧没有任何上拉
3V3 ─[RS1 4.7K]─ SCL_MAG ─[R19 10R]─ U5.COM1 ══开关1══ U5.NO1 ─ PB6
                    │                    ↑
                  U6.1(SCL)          IN1 ←[R21 10R]← PA6
```

嫌疑收敛到 `RS1` / `R19` / `R21` / U5 开关1 —— 全是 0201 无源件,与 IST8310 无关。

**教训:凡是"读到高/读到低"的单点电平判据,先问一句这个电平还能从哪来。**
悬空 + ESD 二极管漏电是最容易被当成"正常"的一种。
